Sistema da Cantina da Escola

Desafio CRUD Compacto 2026 · Um sistema, seis times, trinta e seis funções

A cantina da escola precisa de um programa de terminal para cadastrar os lanches, vender, repor o estoque e ver quanto tem no caixa. Cada time constrói um pedaço em um arquivo .py; o sistema só funciona quando todas as peças se encaixam.

🐍 Python puro 🧩 Só funções + dicionários 🚫 Sem classes, sem bibliotecas, sem arquivos 💻 Roda no terminal 👥 6 times × 6 funções = 1 por aluno
Começo

1. Visão geral

O que é CRUD e como o sistema se divide em pedaços.

CRUD é a sigla das quatro coisas que todo sistema de cadastro faz: Criar (cadastrar), Read (ler / listar), Update (atualizar) e Delete (remover). O nosso sistema faz isso com os produtos da cantina e, além disso, vende, repõe estoque e mostra um relatório.

Dividimos o trabalho em seis times. Cada um cuida de um arquivo e de um tipo de tarefa. No meio de tudo fica um único dicionário chamado sistema, onde os dados vivem enquanto o programa roda.

2. Times e funções

Seis times de seis pessoas. Cada time entrega um arquivo com seis funções — uma por aluno, que ele apresenta no final.

Time 1 Tela (prints)

Arquivo: interface.py · prefixo mostrar_

Tudo o que aparece na tela. Não lê teclado e não mexe nos dicionários.

  • mostrar_titulo()
  • mostrar_menu()
  • mostrar_tabela_produtos(produtos)
  • mostrar_recibo(venda, produtos)
  • mostrar_relatorio(resumo)
  • mostrar_mensagem(texto, tipo)
Usa: Time 4 (formatar_dinheiro) e Time 5 (situacao_produto)

Time 2 Teclado (inputs)

Arquivo: coleta.py · prefixos ler_, perguntar_

Todos os input(). Se a pessoa digitar errado, avisa e pergunta de novo — o programa nunca quebra.

  • ler_texto(mensagem)
  • ler_inteiro(mensagem, minimo)
  • ler_decimal(mensagem)
  • ler_opcao(mensagem, opcoes)
  • perguntar_sim_nao(mensagem)
  • ler_dados_produto()
Usa: Time 1 (mostrar_mensagem)

Time 3 Cadastro (guardar e achar)

Arquivo: cadastro.py · prefixos cadastrar_, buscar_, registrar_

Guarda e procura coisas nos dicionários. Inventa os códigos. É a base de todo mundo.

  • gerar_codigo(dicionario)
  • existe(dicionario, codigo)
  • cadastrar_produto(produtos, dados)
  • buscar_produto(produtos, codigo)
  • buscar_codigo_por_nome(produtos, nome)
  • registrar_venda(vendas, venda)
Usa: ninguém (é a base)

Time 4 Cálculos

Arquivo: calculos.py · prefixos calcular_, formatar_

Toda conta do sistema. Recebe números, devolve números. Sem print, sem input.

  • calcular_subtotal(preco, quantidade)
  • calcular_troco(total, valor_pago)
  • calcular_total_vendas(vendas)
  • calcular_media_vendas(vendas)
  • calcular_valor_estoque(produtos)
  • formatar_dinheiro(valor) → "R$ 6,50"
Usa: ninguém (é a base)

Time 5 Estoque

Arquivo: estoque.py · prefixos verificar_, baixar_, repor_

Cuida da quantidade de cada produto. É o único que pode mudar produto["quantidade"].

  • verificar_estoque(produtos, codigo, qtd)
  • baixar_estoque(produtos, codigo, qtd)
  • repor_estoque(produtos, codigo, qtd)
  • situacao_produto(produto)
  • produtos_em_falta(produtos)
  • contar_unidades(produtos)
Usa: Time 3 (buscar_produto)

Time 6 Ligar tudo

Arquivos: atualizacao.py e main.py · prefixos atualizar_, remover_, fluxo_

Altera e remove produtos, cuida do caixa e monta a venda chamando as funções de todo mundo.

  • atualizar_produto(produtos, codigo, campo, valor)
  • remover_produto(produtos, codigo)
  • atualizar_caixa(sistema, valor)
  • fluxo_vender(sistema)
  • fluxo_atualizar_produto(sistema)
  • fluxo_remover_produto(sistema)
Usa: todos os times
O menu principal, fluxo_cadastrar_produto, fluxo_listar_produtos, fluxo_repor_estoque e fluxo_relatorio já vêm prontos em main.py. Eles servem de modelo: o Time 6 copia o jeito e escreve os três fluxos que faltam.

3. Regras e combinados

O que pode, o que não pode, e os combinados para o código de todo mundo encaixar.

PodeNão pode
Funções (def), parâmetros e return
Dicionários, listas, textos, números, True/False
if / elif / else, for, while
input(), print(), f-strings
Métodos de texto: .strip(), .lower(), .isdigit(), .replace(), .ljust()
import dos arquivos dos outros times 		class (orientação a objetos)
Bibliotecas de fora (pandas, rich, etc.)
Salvar em arquivo ou banco de dados — os dados vivem só enquanto o programa roda
global — nada de alterar variável global dentro de função
try / except — valide com .isdigit() e if
Janela gráfica — é tudo no terminal

Combinados obrigatórios

  • Nomes em snake_case: cadastrar_produto, valor_pago. Tudo minúsculo, palavras separadas por _.
  • Verbo no começo, usando o prefixo do time: mostrar_, ler_, buscar_, calcular_…
  • O dicionário sempre chega por parâmetro. Quem precisa mexer em produtos recebe produtos. Nenhuma função usa variável global.
  • Mesmos parâmetros sempre. ler_inteiro recebe sempre dois valores, mostrar_mensagem também. Nada de parâmetro opcional.
  • Retornos combinados: funções que fazem algo devolvem True/False; buscas devolvem o dicionário ou None; cadastros devolvem o código criado; funções mostrar_ não devolvem nada.
  • Códigos são números inteiros começando em 1 (gerar_codigo dá o maior + 1).
  • Dinheiro é float e passa por round(valor, 2) antes de sair de uma função de cálculo.
  • Uma função, uma tarefa. Se passou de 15 linhas, pare e pense.
  • Docstring (o texto entre """ logo abaixo do def) em toda função: o que faz, o que recebe, o que devolve. Já está escrito no esqueleto — não apague.
O que é None? É o "nada" do Python. Quando buscar_produto não acha o código, ela devolve None. Quem chamou testa com if produto is None: e avisa o usuário.
A regra de ouro: só o Time 6 chama funções de todos os outros. Os demais times usam no máximo um ou dois arquivos vizinhos (veja a seção 6). Isso evita o sistema virar um novelo.

    },
    "vendas": {
        1: {"produto": 1, "quantidade": 2, "total": 12.0},
    },
    "caixa": 12.0,

sistema["produtos"][1]["nome"]        # "Coxinha"
sistema["produtos"][3]["quantidade"]  # 4
sistema["vendas"][1]["total"]         # 12.0
sistema["caixa"]                      # 12.0

Por que a função consegue alterar o dicionário sem return? Quando você passa um dicionário para uma função, ela recebe o mesmo dicionário, não uma cópia. Então produtos[codigo]["quantidade"] = 5 dentro de baixar_estoque muda o dicionário que está em main.py. Por isso não precisamos de global.

Roteiro para testar o sistema inteiro

Rode python main.py e siga os passos. Os valores esperados estão em negrito — se bater, está certo.

  1. Começar — o sistema sobe com 3 produtos de dados.py: Coxinha (R$ 6,00 × 20), Suco (R$ 4,50 × 10), Pão de queijo (R$ 3,00 × 4, situação BAIXO).
  2. Cadastrar — Brigadeiro, preço 2,50, quantidade 30. Deve receber o código 4. Listar e conferir.
  3. Vender — 2 coxinhas, pagando R$ 20,00. Total R$ 12,00, troco R$ 8,00. Coxinha fica com 18.
  4. Tentar vender demais — 5 pães de queijo (só tem 4). Sistema deve avisar "Só temos 4 em estoque" e voltar ao menu sem mudar nada.
  5. Repor — chegaram 10 pães de queijo. Fica com 14 e situação OK.
  6. Digitar errado — em "Código do produto", digitar abc. Deve aparecer erro e perguntar de novo, sem quebrar.
  7. Atualizar — mudar o preço da coxinha para 7. Listar: deve mostrar R$ 7,00.
  8. Remover — remover o suco (código 2), confirmando com s. Listar: só sobram 1, 3 e 4.
  9. Relatório — 1 venda, total R$ 12,00, média R$ 12,00, 62 unidades (18 + 14 + 30), valor do estoque R$ 243,00 (18×7 + 14×3 + 30×2,5), caixa R$ 12,00.
  10. Sair — opção 0 mostra "Até logo!" e encerra.

13. Montagem e apresentação

Como sair de seis arquivos soltos para um sistema que roda — e como cada aluno apresenta a sua função.

  1. Ler o contrato (todos) — cada time lê a sua tabela da seção 12 e abre o seu arquivo em esqueleto/. Cada aluno escolhe uma função. Dúvidas sobre nome, parâmetro ou retorno são tiradas antes de programar.
  2. Testar com os mesmos dados (todos) — todo mundo usa dados.py com criar_sistema(). Assim "deu 12,00 aqui" significa a mesma coisa para o colega.
  3. Programar a própria função (cada aluno) — trocar o pass # TODO pelo código. Rodar python nome_do_arquivo.py: o bloco de testes no fim do arquivo mostra o resultado e o esperado lado a lado.
  4. Montagem 1 — cadastrar e listar — juntar os arquivos numa pasta e rodar python main.py. Opções 1 e 2 precisam funcionar. Envolve T1, T2, T3, T4, T5.
  5. Montagem 2 — vender — Time 6 termina fluxo_vender. Roteiro da seção 11 até o passo 5.
  6. Montagem 3 — atualizar, remover, relatório — roteiro da seção 11 completo.
  7. Tentar quebrar (teste cruzado) — cada time testa o sistema tentando derrubá-lo: letra onde é número, código que não existe, Enter vazio, quantidade zero. Bug encontrado vai para o time dono da função.
  8. Apresentação (cada aluno, 2 minutos) — mostra a sua função e responde três perguntas: o que ela recebe? o que ela devolve? quem chama ela (ou quem ela chama)?

Como rodar

# dentro da pasta com os 8 arquivos .py
python main.py          # o sistema inteiro
python cadastro.py      # só os testes do Time 3 (idem para os outros arquivos)

14. Para quem terminar antes

Ideias que continuam dentro das regras: só funções e dicionários.

Vender pelo nome

A função buscar_codigo_por_nome do Time 3 já existe. Em fluxo_vender, deixe a atendente digitar "coxinha" em vez do código.

Listar vendas

Uma opção 8 no menu que percorre sistema["vendas"] e chama mostrar_recibo para cada uma.

Produto mais vendido

Somar a quantidade vendida de cada produto a partir de vendas e mostrar o campeão no relatório.

Venda com vários itens

Em vez de um produto por venda, um while que pergunta "Mais um item?" e guarda {codigo: quantidade}. É assim que a versão completa do desafio funciona.

Time 7 — Testadores

Se a turma for maior, um sétimo time só para escrever o roteiro de teste (seção 11) e caçar bugs nos outros. Eles não escrevem funções do sistema — escrevem funções de teste.

Função de mentira

Enquanto a função do colega não fica pronta, o Time 6 pode usar uma versão falsa que só devolve um valor fixo (ex.: return True). Assim o menu já roda no primeiro dia.
